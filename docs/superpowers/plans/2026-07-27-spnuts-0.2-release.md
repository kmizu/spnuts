# SPnuts 0.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish SPnuts 0.2.0 with mandatory gradual typing documented and verified in the packaged JVM and Linux Native distributions.

**Architecture:** Keep the proven 0.1.0 packaging and single-bundle Release/Pages workflow. Update synchronized version and release-facing documentation, strengthen packaged-runtime and workflow contracts, then merge, tag, publish, and audit the external artifacts.

**Tech Stack:** Scala 3.3.1, sbt, Scala Native, Bash, GitHub Actions, GitHub Releases, GitHub Pages.

## Global Constraints

- Version is exactly `0.2.0`; the immutable release tag is `v0.2.0`.
- The release is cut from current `main`; no additional language feature is added.
- JVM bundle is self-contained and requires Java 17+.
- Native bundle is Linux x86_64 only; Java interoperation remains JVM-only.
- GitHub Release and Pages expose the same two archives and `SHA256SUMS`.
- Mandatory gradual typing has no opt-in or disable flag.
- Packaged JVM and Native launchers must reject an incompatible complete chunk before any side effect runs.
- The original dirty checkout at `/home/mizushima/repo/spnuts` is never modified.

```markdown
# SPnuts 0.2.0

SPnuts 0.2.0 introduces mandatory gradual typing while keeping the language
usable at dynamic Java, host, and `eval` boundaries.

## Highlights

- Every complete chunk is type-checked before execution; checking is not optional.
- Unannotated bindings receive inferred fixed types.
- `val` is immutable; `var` and legacy assignment remain mutable within their type.
- Explicit annotations, generic functions, and recursive structural compatibility are supported.
- `Any` marks dynamic boundaries, with runtime guards at concrete annotations.
- `Long` widens implicitly to `Double`; primitive annotations reject `null`.
- REPL type errors include expected/actual types, source position, and a caret.
- Successful inferred types persist transactionally across REPL chunks and packages.

## Compatibility note

Code that reassigns one binding to unrelated runtime types may have executed
under SPnuts 0.1.0. SPnuts 0.2.0 rejects that complete chunk before any of its
side effects run.

## Downloads

- JVM distribution: Java 17+ on macOS, Linux, and Windows.
- Native distribution: Linux x86_64.
- Java interoperation is available only in the JVM distribution.

Verify downloads with the published `SHA256SUMS`.
```

### Task 3: Prove mandatory typing in packaged launchers

**Files:**

- Modify: `scripts/test-package-release.sh`

**Interfaces:**

- Consumes: extracted JVM and Native `bin/spnuts` launchers.
- Produces: a platform-symmetric release contract for valid fixed typing and whole-chunk rejection before side effects.

- [ ] **Step 1: Replace the arithmetic-only smoke fixture**

After extracting both archives, create:

```bash
cat > "$work/valid.pnuts" <<'EOF'
var count = 1
count = count + 1
println(count)
EOF

cat > "$work/invalid.pnuts" <<'EOF'
println("SHOULD_NOT_RUN_BEFORE")
count = 1
count = "two"
println("SHOULD_NOT_RUN_AFTER")
EOF
```

Add this helper:

```bash
verify_launcher() {
  local launcher=$1
  local platform=$2
  local valid_output="$work/$platform-valid.txt"
  local invalid_output="$work/$platform-invalid.txt"

  "$launcher" "$work/valid.pnuts" > "$valid_output"
  grep -Fx '2' "$valid_output"

  "$launcher" "$work/invalid.pnuts" > "$invalid_output"
  grep -F 'Type error at <repl>:3:9:' "$invalid_output"
  grep -F 'expected Long, actual String' "$invalid_output"
  if grep -F 'SHOULD_NOT_RUN_' "$invalid_output"; then
    echo "$platform launcher ran side effects before rejecting the chunk" >&2
    exit 1
  fi
}
```

Invoke it for both launchers:

```bash
verify_launcher "$work/jvm/spnuts-$version-jvm/bin/spnuts" jvm
verify_launcher "$work/native/spnuts-$version-linux-x86_64/bin/spnuts" native
```
